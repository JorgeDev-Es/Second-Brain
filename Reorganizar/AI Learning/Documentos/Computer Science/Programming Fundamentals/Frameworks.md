# Frameworks
While high-level abstractions are essential for building complex, maintainable, and efficient real-world applications, diving into very low-level development provides invaluable insights into how software and hardware truly interact. It builds a foundational understanding that makes you a more effective developer even when working with higher-level tools and languages.
## When to use a framework?
Using a framework indeed offers significant advantages, especially in terms of abstraction and long-term maintainability, compared to building an application purely with low-level tools or direct OS APIs.

### Improved maintainability and robustness
When you use a well-maintained framework:
- Bug-fixes: The framework developers and community continuously find and fix bugs that might exist in the framework itself or that arise from interactions with the underlying operating system, libraries, or hardware.
- **Security Updates:** If security vulnerabilities are discovered in how the framework interacts with the system (e.g., handling input, networking, rendering), the framework maintainers are responsible for patching them, and you benefit by updating the framework version.
- **Compatibility:** Frameworks often handle compatibility issues across different operating system versions, different platforms (if the framework is cross-platform), and even different underlying libraries. They absorb the complexity of dealing with variations and updates in the lower layers.
- **Performance Improvements:** Framework developers often optimize core functionalities, leading to performance gains in your application just by updating.
- **New Features and Best Practices:** Frameworks evolve, incorporating new features, supporting newer platform capabilities, and integrating modern best practices.
